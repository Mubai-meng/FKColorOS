## 0. 一句话结论

全部 hook 点已在本机 `oplus-services` 反编译源码 / `oplus-framework.jar` / `系统桌面_17.3.12.apk`
里逐个核对过签名与行号。**上游照搬有三处会静默失效**，见 §4。

### 为什么 2 要勾「系统桌面」

多任务卡片列表不是 system_server 画的：Launcher 拿到 `GroupedTaskInfo` 后由
`ko.a`（本机混淆名，语义 = `OplusRecentTasksFilter`）做过滤。上游同样是双进程拆分，
设置页那条 summary「需要勾选系统桌面」就是提示这件事。

## 3. 实现要点（改动前必读）

1. **数量上限必须两处一起改**：只改 `getMaxWinNum` 时能开出第 4 个小窗，但
   `getTasksNumber` 仍按旧的 4 取任务 ⇒ 新窗口背后那个全屏任务查不到 ⇒ **小窗背后是黑的**。
2. **`avoidOverlappingAreas` 是"后置微调 `Rect.top`"**：`Rect` 由调用方持有，
   必须 `offsetTo` 原地改；换对象等于没改。
3. **横屏比例只在 `args[4] == true` 时介入**（`isLandscapeOrientation`），
   且候选比例列表里**没有任何 `<1` 的比例**时也不介入（该应用不允许横屏）。
4. **`mSecurityMarginRight` 必须成对还原**：`regulateSizeIfOverScreen` / `getTaskRealSize`
   是实例字段，改了不还原会永久污染布局策略（小窗再也不被裁到屏内）。用 `ThreadLocal` 存旧值。
5. **白色竖条必须拦 `updateViewLayoutParams`**：框架每次布局都用"整条把手宽度"覆盖容器宽度，
   只改 `updateIconStyle` 会被下一次布局覆盖回去。
6. **贴边挂机是"四个钩子装全才接管"**：`coreReady` 为假时 `moveTaskToBackForPanorama` 直接放行。
   少了 `canReceiveKeys`/`canReceiveTouchInput`/`prepareSurfaces` 任何一个，
   就会出现"小窗还在但点不动、背后窗口也没焦点"的死状态 —— 宁可退回原生。
7. **静音的原值必须从 `mMusicVolumeMap` 读**，且同一应用重复贴边时不能把 0 记成原值。
8. **热路径门控**：`canReceiveKeys` / `prepareSurfaces` / `setFocusedTask` 都是高频入口，
   全部以 `hungIds.isEmpty()` 先短路，再读开关。

## 4. 与上游的差异（三处会让上游静默失效 / 行为不符）

| 项 | 上游 | 本模块 | 原因 |
|---|---|---|---|
| `switchToFullMode` | 固定按 **4 参** `findAndHookMethod` | 遍历所有重载，判 `parameterTypes[0] == FloatHandleInfo` | 本机是 **5 参**（多了 `boolean growthAnim`）⇒ 上游按 4 参查会 `NoSuchMethodError` 并被 catch 掉，白条"吸附后"这一路永远不生效 |
| 小窗判定 | 先 `TaskUtils.isFlexibleFloatingWindow`，再 `FlexibleWindowManager#getFlexibleWindowState` | 直接走 `getFlexibleWindowState(TaskInfo)==1`，最后兜底 `windowingMode==5` | 本机 Launcher **没有** `TaskUtils` 类（`classes` 表 0 行） |
| 关闭态记录 | `XposedHelpers.setAdditionalInstanceField(task, CLOSED, generation)` | `HashSet<String>` 存 `userId:taskId` + 开关翻转时清空 | 本模块 `Reflect` 没有 additional instance field 能力；键值与 `RecentTaskInfo`/`Task` 两组字段名都对齐，行为等价 |
| 重新打开检测 | `moveToFront` + `onAppFocusChanged` + TaskFragment RESUMED 三路 | 同上（保留三路） | 少任一路会出现"关掉后再点开，多任务里还是不见" |
| `exitFlexibleTask` | 额外 hook 三个 `ExitFlexibleTaskTo*Strategy#handleEvent` | 只 hook 7 参 `exitFlexibleTask`（4 参会转调它） | 4 参 → 7 参转调是本机实证（:7952），单一汇聚点更稳 |

## 5. AOSP 侧钩子复核（`E://WorkBuddy_All//APP//oneplus//services.jar`，44.5MB / 4 dex / 26651 类）

> 早期版本曾以为本机"只有 oplus 增量反编译产物"，据此把 AOSP 侧全按上游照抄。
> 实际 `services.jar` 是完整的，下面每一条都是直接查表/反汇编确认的结论。

### 5.1 多任务列表的完整数据通路（这条决定 hook 点选哪里）

```
系统桌面  com.android.wm.shell.recents.IRecentTasks#getRecentTasks
   ↓ binder
系统界面  RecentTasksController#getRecentTasks(III)        ← 只有 5 条指令
            ActivityTaskManager.getRecentTasks(III)         ← 传统 API
   ↓ binder
系统      ActivityTaskManagerService#getRecentTasks
            → RecentTasks#getRecentTasks(IIZII)             ← 5 条指令，new ParceledListSlice(Impl)
            → RecentTasks#getRecentTasksImpl(IIZII)         ← 332 条指令（不会被内联）
```

结论：

- 在 `com.android.server.wm.RecentTasks#getRecentTasksImpl` 拦截**确实**能影响 ColorOS 多任务列表；
- 但**不要**去 hook `com.android.wm.shell.recents.RecentTasks` —— 那是 Shell 侧的存储类，
  全类只有 `getRecentTasks` / `addAnimationStateListener` / `setTransitionBackgroundColor` 三个方法；
- Shell 的任务集合由 `ShellTaskOrganizer#onTaskAppeared/onTaskVanished` 与
  `RecentTasksController#onRecentTaskListUpdated` 在 SystemUI 进程内自维护。

### 5.3 由此修掉的三个真 Bug

1. **`Task#mLastSurfaceShowing` 在本机不存在** —— `fields` 表全库搜 `SurfaceShowing` 为 **0 行**。
   原实现靠"把该字段改回 false 让框架下一轮自己 show"，实际是空操作 ⇒ 挂机释放后
   画面可能一直黑。已改为释放时显式 `getSyncTransaction().show(surface)`。
2. **隐藏名单未与实时任务交叉校验** —— `taskId` 会被系统回收复用，只按键匹配会把
   **后来新建的无关任务**一起吞掉。已改为 `closedKeys ∩ RecentTasks#getRawTasks()`，
   并在 `RecentTasks#remove(Task)` 时清记录。
3. `TaskExtImpl` 的 `getLaunchScenario` / `isTaskEmbedded` / `isHasCaption` 声明在接口
   `ITaskExt` 上、实现可能落在父类 ⇒ `callByName`（只查精确类 declaredMethods）恒返回 null，
   已改 `callDeep`。

### 5.4 仍然存在的风险

- 贴边挂机的"应用继续在台前跑"依赖原生贴边流程走 `moveTaskToBackForPanorama`；
  若某版本改成直接 `moveTaskToBack`，功能会失效（日志无 edge_hang 记录）。
- 任一方法找不到只会记一行 `W` 并跳过该子功能，不影响其它七项。

## 6. 真机验证清单

1. **数量上限**：开关打开、上限设 4 → 连续开 4 个小窗都能开；第 4 个背后的桌面/全屏应用
   仍可见（不是黑屏）；关掉开关后回到原生上限。
2. **多任务隐藏小窗**：开一个小窗 → 进多任务 → 该卡片**不出现**；分屏（两张卡）不受影响；
   必须已勾选 `com.android.launcher` 作用域。
3. **关闭小窗后隐藏**：开小窗 → 关闭（退到后台）→ 进多任务 → 无该卡片；
   再从桌面点开该应用 → 进多任务 → 卡片**恢复**。
4. **贴边挂机**：开小窗 → 贴边 → 应用继续播放/下载（不被冻结）；点小窗恢复原状态；
   日志里应出现 `edge_hang: 跳过 moveTaskToBack, taskId=…`。
5. **静音**：先开挂机开关再开静音 → 贴边后无声 → 点回小窗后音量恢复原值。
6. **白色竖条**：贴边后屏幕右缘是一条 4dp 白色胶囊，无图标；点开小窗后把手样式恢复正常。
7. **横屏保持比例**：横屏视频应用开小窗 → 画面比例正常（不是竖屏拉伸）。
8. **贴边尺寸**：小窗拖到最大 → 左右各留约 8dp，不再被巨大的安全边距挡住贴不到边。
