# 主题商店 + 主题基础服务（解锁会员 + 去广告）- 移植与实证

> 宿主：`com.heytap.themestore`（**主题商店 17.11.21**）＋ `com.oplus.themestore`（**主题基础服务 17.11.21**）
> 代码：`hook/hookers/ThemeStoreHook.kt`、`ui/compose/scopes/apps/ThemeStorePage.kt`
> 来源：`fuckapp`（本地参考项目）＋ `ONextBox`（GPL-3.0，`ThemeStoreHooker` / `ThemeStoreAdsHooker`）
>
> 两个包出自**同一份 themespace 代码库**、类名一致，但裁剪不同：
> 商店有 UI/广告/到期广播，基础服务只有 DTO 与 apply（资源应用、试用还原）。
> 因此 hooker 按包名分流（见第 5.2、7 节），scope.list 两个都加。

---

## 1. 需求与归并

两个来源覆盖的功能有大量重叠，本次移植**先适配本机版本、再合并重复 hook**，最终落成三个开关：

| 开关（prefs key） | 覆盖内容 | 来源 |
|---|---|---|
| `theme_store_vip` 解锁会员功能 | 会员状态链、资源卡会员标记、详情页价格 | 两边都有（合并） |
| `theme_store_remove_ads` 去除开屏与广告卡片 | 开屏广告、首页横幅、信息流广告卡 | 两边都有（ONextBox 更完整） |
| `theme_store_keep_trial` 试用资源不过期 | 到期广播（商店）＋ 还原执行体（基础服务） | 两边都有（合并） |

**重复项只保留一份**：`VipUserDto#getVipStatus`、`WeatherPageResponseDto#getVipStatus`、
`ResourceItemDto#getIsVip/getIsVipAvailable`、`SplashDto` 广告字段、`ThemeTrialExpireReceiver`
原先在两套规则里各挂一次（`fuckapp` 的 DeerHooks + FuckHooks + DexQueries 三处也彼此重复），
移植后每项只挂一次，由开关统一控制。

## 2. 版本适配（关键）

`fuckapp` / `ONextBox` 的部分符号在 **17.11.21 上已不存在**，直接照搬会「零日志静默不装」：

| 上游写法 | 本机 17.11.21 实际情况 | 处理 |
|---|---|---|
| `VipExpireManager#checkAndShowExpiredDialogIfNeed`（fuckapp DexQueries） | 该类**不存在** | 丢弃；改用「`VipUserDto#getEndTime` 恒远期」从根上不产生过期态 |
| `com.nearme.themespace.fragments.i7#A1 / C1`（ONextBox 首页弹窗） | `i7` 里没有 `A1/C1`，方法名整批重排 | 丢弃（本版未找到等价稳定入口） |
| `lo.a$c` / `xq.a$c` 促销弹窗（ONextBox） | `lo.a` 是**命令分发器**（`a(Context,IResultListener)` → `lo.b/lo.c`），与弹窗无关 | 丢弃 |
| `ad.l#J(SplashDto)` 作为「无广告收尾」 | 本版 `J()` 是**无参** `()V`（`I()` 的无广告分支在 `label_006f`） | 改为 hook `y(SplashDto)Z` 返回 false，走同一条原生分支 |
| `ad.l$c(l, FragmentActivity)` 构造器 | 本版是 `l$c(l, SplashDto)` | 不需要（不构造宿主对象） |
| `SplashBaseAdViewImpl#bindData`（fuckapp） | 该类不存在 | 丢弃，由 `y()` + DTO 双重拦截覆盖 |
| `TemplateAdCardDTO` / `SearchBannerAdCardDto` | 本版只剩 `AdCardDto`、`GoodsAdCardDto` | 名字保留在集合里（不存在无副作用），实际生效 2 个 |
| `ResourceItemDto#getIsVip` 返回 boolean（fuckapp `HookAction.TRUE`） | 实际是 **`Ljava/lang/Integer;`** | 改为返回装箱 `1`；类型不符时宁可不挂（返回 Boolean 会 CCE） |

## 3. 会员链路（本机反汇编）

```
UserInfoManager#P()                      ← 全 App 会员状态唯一汇聚点
  ├─ U()         未登录 ⇒ INVALID
  ├─ C() 为空    ⇒ INVALID
  ├─ q3#o() 取 VipUserDto，为 null ⇒ CHECKING
  ├─ T(dto)      endTime>0 且 now>=endTime ⇒ CHECKING（**过期覆盖**）
  └─ dto.getVipStatus()==1 ⇒ VALID，否则 INVALID
```

结论：**只改 `getVipStatus` 不够** —— 真实账号若已过期，`getEndTime` 会让 `T()` 先判过期。
因此同时把 `getEndTime` 抬到 2100-01-01。未登录/无账号时链路仍走原生 INVALID（不伪造登录态）。

`je.a#w/x/y`、`s0`、各 `*PageHolder`、`cards/impl/*` 都从这里取值，改一处即可全局生效。

挂载清单（`hookVip`）：

| 类 | 方法 | 返回 |
|---|---|---|
| `VipUserDto` | `getVipStatus()` | 1 |
| `VipUserDto` | `getVipDays()` | 999 |
| `VipUserDto` | `getEndTime()` | 4102444800000（2100-01-01Z） |
| `WeatherPageResponseDto` | `getVipStatus()` | 1 |
| `ResourceItemDto` | `getIsVip()` / `getIsVipAvailable()` | 1（Integer） |
| `PublishProductItemDto` | `getIsVipAvailable()` / `getPrice()` | 1 / 0.0 |
| `ThemeGroup`（H5 JS 接口） | `isVip()` | true |

**边界**：只影响客户端判定与展示。真实购买/下载仍需服务端授权，
「会员资源能否下载」以客户端校验为准，服务端强校验的资源会失败 —— 与上游说明一致（「实际效果因资源而异」）。
不触碰订单、支付、账号态。

## 4. 广告链路

### 4.1 开屏

`ad.l` 是开屏管理器：

- `a(FragmentActivity,int,boolean)` 入口：请求广告 + `sendEmptyMessageDelayed(4, 3000)`；
- `E()` 处理 message 4（onTaskComplete）→ `I(SplashDto)`；
- `I(SplashDto)`：
  ```
  if (dto == null) goto label_006f
  if (!y(dto))     goto label_006f
  ... 展示 splash view ...
  label_006f:  f("onShowLocalSplash"); J(); callback.f0(false)   ← 宿主原生「无广告」收尾
  ```
- `y(dto)`：时间窗（`getStartTime`/`getEndTime`）+ `self.f#M(context,dto)`（自有素材是否可用）。

因此 **hook `y()` 返回 false = 走宿主自己的无广告路径**：清计时器、`J()` 通知 splash owner、
`f0(false)` 告知调用方继续。比「改实参为 null」更安全（不涉及 `proceed(args)` 的参数个数问题）。

再加两道保险，覆盖不经 `y()` 的分支（如登录回调里 `self.f#O(...)` 直接展示自有素材）：

- `ad.self.f#M(Context,SplashDto)Z` → false（自有素材不可用）
- `SplashDto#getAdData` → null、`getShowTime` → 0、`getIsSkip` → true

### 4.2 卡片与横幅

- `HomePageDto#getAdBanner()` → null；
- 11 个卡片容器的列表 getter（`getCards` / `getTabs` / `getRankCards` / `getTopicList` / `getItems`）
  在 `proceed()` 之后过滤：沿继承链命中 `AdCardDto` / `GoodsAdCardDto` 即剔除。
  返回**新列表**（宿主可能给不可变集合），原生也允许空列表，不会 NPE。

### 4.3 为什么不做「营销弹窗」

17.11.21 里 ONextBox 的两个弹窗入口（`i7#A1/C1`、`lo.a$c`）都已不存在或语义变了。
本版 `PromotionPopupDto` 只剩 `getUrl/getContentStat`，其持有者（`ir.c`、`ir.l$*`、`ts.*`、
`mr.a#g`）都是状态/上报对象，没有稳定的「是否展示」闸门。**宁可不做，也不乱挂**：
错挂一个 UI 生命周期方法可能导致首页空白或弹窗永久卡住。后续若定位到稳定闸门再补。

## 5. 试用资源不过期

试用到期有**两段**：商店收到广播（决定「已过期」）→ 基础服务执行还原（把主题打回默认）。
只拦广播不够稳，所以两个宿主各拦一段。

### 5.1 商店侧：到期广播

`ThemeTrialExpireReceiver#onReceive(Context,Intent)` 是 6 类到期广播的唯一处理点：

```
THEME_TRIAL_EXPIRE / FONT_TRIAL_EXPIRE / LIVE_WP_TRIAL_EXPIRE /
SKU_SYSTEMUI_TRIAL_EXPIRE / SKU_LOCKSCREEN_TRIAL_EXPIRE / RESOURCE_EXPIRE
```

命中这 6 个 action 时直接 `return null`（跳过），其余 action（如 `CALL_ACTIVE`）原样放行。

### 5.2 基础服务侧：还原执行体

`com.oplus.themestore` 里**没有**这个 Receiver，但有真正的还原动作：

`nd.s`（`source_file = AtomTrialRecoverApplyManager.java`，构造 `(Context, ApplyParams, apply/d)`）
的 `e0()V` 遍历校验器（`TrialRecoverResInstallValidate` = `hd.l`、`hd.*` 等），
任一个 `pd.d#b()` 为 false（或 `a()` 返回 null）就 `qd.b#u()` **恢复默认主题**。

- hook 点：`nd.s#e0()V` → 开关打开时直接 `return null`，整段还原流程不执行；
- 安全性：父类 `resourcemanager.apply.b` 里**没有** `e0`（已核对），`nd.s` 是 trial-recover
  专用 manager，普通主题应用走别的 manager，不会误伤；
- 混淆名很脆：用构造签名 `(Context, ApplyParams, resourcemanager.apply.d)` 做锚点，
  锚点或 `e0()V` 任一不符就只打 WARN 跳过（宁可失效，不误挂）。

## 6. 性能与功耗

| 关注点 | 做法 |
|---|---|
| 轮询/定时器 | **无**。全部是 getter / 列表 getter / 广播接收。 |
| 开关读取 | `Flags` 做 **1s TTL 快照**：热路径只读 volatile 布尔，每秒最多回读一次 remote prefs。 |
| 列表过滤 | 先 `none(isAd)` 短路；无广告直接返回原生列表，零分配。 |
| 类加载 | 只用固定类名 + `Reflect` 缓存；**不引入 DexKit**（60MB/5dex 建索引数百 ms 且常驻内存，收益不抵）。 |
| 失败代价 | 任何类/方法缺失只打一次 WARN 并跳过，不影响宿主启动与其它 hook。 |
| 混淆名风险 | `ad.l` / `ad.self.f` 随应用升级可能改名；`y()` 按「唯一 (SplashDto)→boolean」形状兜底，仍失败则 WARN（不静默）。 |
