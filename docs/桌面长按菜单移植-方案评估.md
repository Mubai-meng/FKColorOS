> 功能来源：`E:/WorkBuddy_All/workbuddytask/FuckColoros/fkfluidcloud`「功能七 · 系统桌面 App 图标长按菜单」（`hook/LauncherMenuHook.kt` + `ui/screen/LauncherMenuScreen.kt`，演进至 v1.6.16+）。
> 逆向素材：`E:/WorkBuddy_All/APP/oneplus/decompiled/launcher`（系统桌面 17.3.12，ColorOS 17 / Android 17 / OnePlus 15）。
> 目标：移植进 ColorOSTools（libxposed API 102），并在移植前评估**更优雅、对系统性能影响更小**的实现方案。

### 关键实证结论

1. **`buildPopupData(View)` 是全部菜单数据的唯一总装点**（PopupMenuPresenter.java:654）——一级系统项、深链列表、堆叠组在返回前全部定型。
2. **宿主自己对 `systemShortcutsIn` 逐项问 `isEnabled()`**（COUIPopupListWindowContainer.java:1729/1901/1825）——在数据层删掉实例，等价于让该项「被禁用」，无需钩 `isEnabled()` 本身。
3. **`segments()` 是渲染与点击的公共上游**，且 `onItemClick` 每次点击实时重调它 —— 换掉深链段的 `onClick` 即同时换掉点击行为；改段内 entry 的 coui 行模型字段即同时改掉渲染数据。
4. **coui 行模型 `com.coui.appcompat.poplist.g` 的字段**（g.java）：`f24286j`(int 图标 resId) / `f24287k`(Drawable 图标) / `f24289m`(String 文案) / `f24296t`(子菜单 g 列表)。
5. **`MordFunctions` 的两个子列表在构造函数里严格同步 add**（2527-2560：同一个 `if (isEnabled())` 块内两个列表各 add 一次）——下标一一对应；清子项必须两个列表同步清（渲染用 `popupListItems`，平铺取 `mMoreSystemShortcutList`）。
6. **深链段 onClick 自带 `getReady()` 守卫**（BasePopupListWindowContainer.java:1017）：初始 entry（ready=false）点击无行为；异步回填后才可点。
7. **`currentVisibleDeepShortcutLimit()` 子类覆写返回 `Integer.MAX_VALUE`**（COUIPopupListWindowContainer.java:982-984），`segments()` 对 `mDeepShortcuts` 做 `take(limit)` —— 原生就带「可见数量」闸门。

## 3. 原实现（fkfluidcloud v1.6.16+）的钩子链：11 个

| # | 钩子 | 职责 |
|---|---|---|
| 1-6 | `OplusBaseSystemShortcut$Xxx#isEnabled()` × 6（PrivacyLock/ClosePrivacyLock/OplusAppInfo/AppShare/AppEdit/CardAdd） | 按项隐藏（同时覆盖一级与「更多」子菜单两级） |
| 7 | `COUIPopupListWindowContainer#populateAndShow(View, PopupMenuData)` | 平铺（重写 systemShortcutsIn）+ 隐藏深链（清 shortcutInfoList）+ 留存 MordFunctions 实例 |
| 8 | `COUIPopupListWindowContainer#currentVisibleDeepShortcutLimit()` | 收起态返回 1（原生只渲染第一个深链） |
| 9 | `BasePopupListWindowContainer#segments()` | 收起态换深链段 onClick 为「展开」；展开态丢系统快捷方式段；记 foldOffset |
| 10 | `COUIPopupListWindowContainer#applyShortcutInfoCompat(int, wii, si)` | ThreadLocal 记 index 0 的 ShortcutInfo id；折叠行换图标 |
| 11 | `PopupListItemConverter#resolveShortcutLabel(ShortcutInfo, Context)` | ThreadLocal 命中 id → 返回「应用快捷方式」 |

原方案的历史包袱（注释里已记）：6 个 `isEnabled` 逐类钩 + `declareOwn` 防呆（防钩到基类 Method 导致一整排菜单消失）；`resolveShortcutLabel` + ThreadLocal 跨钩子传 id；`applyShortcutInfoCompat` 兼管图标。

## 4. 新方案：3 个钩子（本次移植采用）

### 4.1 钩子 A —— `ShortcutDataBuilder#buildPopupData(View)` 后置（数据层，每次长按 1 次）

在**数据总装唯一上游**一次性完成「按项隐藏 + 平铺 + 隐藏深链」：

| 开关 | 数据层动作 |
|---|---|
| 按项隐藏（6 项） | ① `getSystemShortcutsIn()` 删 6 个目标类实例；② 找到 `MordFunctions` 实例，按 `mMoreSystemShortcutList` 的类名定位下标，**同步**删 `popupListItems` 同下标（两列表构造时同步 add，实证） |
| 批量隐藏 | 等价于 6 项全开（同一道过滤） |
| 平铺 | 把 `MordFunctions` 换成 `mMoreSystemShortcutList` 的孩子；去重判据 = 一级同名项在原列表里 `isEnabled()==true`（保留 fkfluidcloud 教训）；**并入时再过一遍按项隐藏过滤**（否则「隐藏应用详情 + 平铺」会让已删的项从子菜单复活） |
| 隐藏深链 | `getShortcutInfoList().clear()`（宿主 `z16` 判空跳过整个深链分组） |
| 折叠 | **不动数据**（保留全量，走原生 limit 机制） |

同时在本钩子里**一次性快照 10 个开关**（remote prefs 内存读，无 IO）存进程级单例——桌面弹窗是单例（`currentOpenPopup` WeakReference 机制，COUIPopupListWindowContainer.java:1838-1843），后续钩子体零 prefs 读取。留存 `MordFunctions` 实例供折叠行取图标。

### 4.2 钩子 B —— `BasePopupListWindowContainer#segments()` 后置（段层，每次 refreshList 1 次）

| 状态 | 动作 |
|---|---|
| 折叠开 ∧ 深链>1 | ① **折叠行 = 克隆首项行模型**（复制全部字段后覆盖 `r=true`/`t=[全量深链的 g]`/`m`/`k`）⇒ 宿主适配器**自动渲染展开箭头**（`MixedPopupListAdapter` :1203）、点击后宿主 `b#h()` 自动 `S()` 弹**原生二级面板**；克隆而非直改首项：首项还要以原名/原图标出现在二级面板里（同一个 g 没法在两个列表显示两种文案）；② 合成只含折叠行的 `DeepShortcutEntry`（不污染宿主 entry）；③ 深链段整体替换为新建段（`entries` = 合成条目，`onClick` 换成**压制启动**代理——原生 onClick 会先启动第一个深链，压掉后宿主才走得到展开检查） |
| 其余 | 原样放行 |

**异步自愈**：`applyShortcutInfoCompat` 异步回填会用 `convertAppShortcutWithIcon` **逐项替换** `mDeepShortcuts`（换新的带图标 g）→ 随后 `refreshList()` 重调 `segments()`，本钩子对每个新 g **重做一遍**——`t`（子项列表）**每次渲染都重抓**，二级面板里才不会攥着一串没图标的旧 g（v1.0.25 事故：只在首项换新时重抓 ⇒ 1..N-1 项丢图标）。不需要钩 `applyShortcutInfoCompat`，也不需要 `resolveShortcutLabel` + ThreadLocal 跨钩子传 id。

**折叠行克隆缓存**：克隆按容器缓存 `(首项 entry → 克隆)`，entry 没换就复用同一对象 ⇒ 克隆身份跨渲染稳定，二级面板点开后 `isMySubmenuOpen`（窗口 `Q` 位与折叠行同一对象）的同一性比对才可靠。

⚠️ **拦截器必须 return 改写结果**（段替换是新建列表）；原地突变（改 g 字段）才不需要。v1.0.22 曾因丢弃返回值导致段替换从未生效（点击直接启动深链），v1.0.23 修复。

### 4.3 钩子 C —— `COUIPopupListWindowContainer#currentVisibleDeepShortcutLimit()` 后置（原生 limit）

折叠开 ∧ `mDeepShortcuts.size() > 1` 时返回 1，其余放行（宿主返 MAX_VALUE）。原生 `segments()` 对 `mDeepShortcuts` 做 `take(limit)` ⇒ 只渲染第一个深链（= 折叠行）。

### 4.4 折叠展开 = 复用宿主原生二级面板（2026-10-16 v1.0.24 重构，替代自建动画）

**背景**：v1.0.23 自建了「窗口撑高 + 180ms 错峰淡入」，真机反馈生硬（窗口尺寸一帧跳变、淡入太快）。逆向发现宿主自带成熟机制（「更多功能」用的就是它）：

- coui 行模型 `g` 的 `r`（可用）+ `t`（子项行模型）⇒ 适配器自动画展开箭头；
- 点击后宿主 `b#h()` 自动检查可展开性并调 `b#S(pos, view)`：弹出**二级面板**（第二个 `RoundFrameLayout` + 独立适配器 `f24261y`），带动画 **`cf.l` 按压进度交接**（从手指按下的那行边界展开到目标面板，ColorOS 原生手感）、父行高亮（`f24281e`）、再点父行/点外面自动收起（`COUIPopupMenuRootView#G#t()`）。

本功能因此只做数据层三件小事（见 4.2），**动画与交互全部白嫖原生**。

**二级面板子项点击的唯一接管点**：宿主子项点击（`b#g()` → 窗口 `F` 监听器）**写死指向 MordFunctions**（遍历 `mSystemShortcuts` 找 MordFunctions，点 `moreSystemShortcutList.get(i)`）——深链走这条路会点错甚至静默无操作。⇒ 首次点折叠行时把窗口 `F` 换成模块侧分发器（**字段赋值，不是钩子**）：展开行是我们的折叠行（窗口 `Q` 位与 `foldParentG` 同一对象）⇒ 按 position **直接下标**取全量深链、调**原生段 onClick** 启动 + 关窗；否则（原生「更多功能」面板）⇒ 委托换装前保存的原生分发器，行为与 stock 完全一致。

### 4.5 v1.0.26 真机反馈三处修复（折叠 UX）

| 反馈 | 根因 | 修法 |
|---|---|---|
| 折叠行文案在二级面板里折成两行 | 6 字「应用快捷方式」超出二级面板行宽（一级列表宽，二级窄） | 文案精简为 4 字「快捷方式」（与原生「更多功能」同长的实测下限） |
| 展开后左边图标全没了 | 子项列表只在**首项**换新时重抓；回填是**逐项**替换 mDeepShortcuts，1..N-1 项还攥着回填前没图标的旧 g；而 coui 适配器的图标显示由「列表里任一item 有图标」的 T 位掩码统一控制，一个都没有就整体隐藏 | `t` 每次渲染重抓全量深链的当前 g。**零额外开销**——图标本来就是宿主回填加载好的，只是引用过期 |
| 展开后少了一个快捷方式 | 折叠行直接用首项行模型改 generic 标签 ⇒ 首项的名字/图标被吞，且它的 onClick 被压制 ⇒ 第一个快捷方式既看不见也点不开 | 折叠行改为**克隆**首项行模型（generic 标签 + 箭头），`t` 放**全量**深链 ⇒ 二级面板里每个快捷方式都以原名/原图标出现且可点；克隆按容器缓存保证身份稳定 |

⚠️⚠️ **JADX 花名陷阱（v1.0.24 事故）**：反编译输出里 coui 类的单字母字段被 JADX 显示成
`f24294r`/`f24296t`/`f24250n` 这类花名，**直接拿花名反射必静默失败**（setField 返回 false 被忽略
⇒ 行从未变成可展开 ⇒ 点击无反应）。运行时真名要用 dexdump 从 dex 里挖（本次实证：g 类
`r`=可用位、`t`=子项列表、`m`=文案、`k`=图标；窗口类 b `n`=数据列表、`E`/`F`/`Q`=真名）。
教训：**凡反射 coui/oplus 混淆类的字段，先 dexdump 核实真名，别信 JADX 显示名**。

⚠️ 全程不碰 `reorderAndShow()`（宿主自己在 `populateAndShow` 末尾调它安全；弹窗开着时手动调会挂 `PopupBlurView` → 整屏模糊，fkfluidcloud v1.6.13 事故教训）。

## 5. 方案对比

| 维度 | 原方案（11 钩子） | 新方案（3 钩子） |
|---|---|---|
| 钩子总数 | 11 | **3** |
| `isEnabled()` 逐类钩 | 6 个（+`declareOwn` 防呆） | **0**（数据层删实例，宿主 populateAndShow 自然过滤，实证 :1729） |
| 每次长按的钩子体调用 | ~40 次 `isEnabled` + 1 次 populateAndShow + 1 次 limit + N 次 segments + N 次 applyShortcutInfoCompat + N 次 resolveShortcutLabel | 1 次 buildPopupData + 1 次 limit + ~3-10 次 segments |
| 跨钩子传态 | ThreadLocal 传 ShortcutInfo id（apply→resolve 两个钩子配合） | **无**（segments 单钩子内改数据，异步自愈） |
| 热路径 prefs 读取 | 每个钩子体各自读（~50 次/长按） | buildPopupData 一次快照，后续钩子体零读取 |
| 反射量 | applyShortcutInfoCompat 钩子每次深链回填都反射一堆 | 仅在 segments 命中收起态时改 2 个字段（`getItem`/`setField` 均走 Reflect 缓存） |
| 混淆鲁棒性 | 依赖 6 个内部类名 + 2 个私有方法名 + ThreadLocal id 语义 | 依赖 3 个公开/半公开方法（按形状定位：`buildPopupData(View)→PopupMenuData`、`segments()→List`、`currentVisibleDeepShortcutLimit()→int`） |
| 主要风险 | 钩子落错类 → 整排菜单消失（靠 declareOwn 防） | `MordFunctions` 双列表下标对应关系（构造时同步 add 实证；失效时仅「更多」里按项隐藏不生效，一级仍生效，降级可接受） |

**性能结论**：长按菜单本身是低频交互（用户手动长按节奏），原方案的绝对开销也不大；但新方案把「钩子数量 / 每次交互的拦截次数 / 跨钩子传态 / prefs 读取」全部压缩到约 1/10，且热点（segments）上的动作从「反射一堆 + ThreadLocal」变成「改两个字段」，语义更直白、宿主演进时的失效面更小。桌面是常驻进程，钩子装一次长期有效，**更少的钩子 = 更小的长期注入面**。

## 6. 风险与降级（全部独立 runCatching，失败只记 W 日志并放行）

| 风险 | 降级行为 |
|---|---|
| `buildPopupData` 找不到（宿主大改版） | 全部 10 开关不生效，菜单纯原生 |
| `segments()` 找不到 | 平铺/按项隐藏/隐藏深链仍生效；折叠退化为「原生全量显示」 |
| `currentVisibleDeepShortcutLimit` 找不到 | 同上 |
| `MordFunctions` 双列表下标对应失效 | 一级按项隐藏仍生效；「更多」子菜单按项隐藏不生效 |
| coui `g` 字段（m/k/r/t）改名 | 折叠行显示第一个深链原名/原图标且无展开箭头（仍可点开），仅美观降级 |
| 压制段构造失败（Function2 类加载不到） | 不替换段 ⇒ 保持原生：点击启动第一个深链（放弃折叠，不造死行） |
| 子项行模型取不到（`getItem()` 全 null） | 同上，放弃折叠 |
| 二级面板 `F` 换装失败 | 面板展开/动画正常，但子项点击走原生 MordFunctions 分发（点错/无操作）；记 W 日志 |
| 桌面崩溃 | 零钩子体抛出：每处独立 runCatching + 安装期类/方法探测；宁可不起效果也不让桌面崩（桌面崩了用户会直接回到锁屏/黑屏，很难自救） |

开关语义门控（与 fkfluidcloud 一致）：
