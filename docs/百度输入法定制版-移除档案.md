## 4. 关键结论与坑（恢复前必读）

### 4.1 性能纪律（输入法进程）

- **禁用 DexKit**：上游在输入法进程启动路径同步跑十余次全量 dex 查询（数百 ms），直接拖慢键盘弹出。本方案用静态定位表，运行时零开销。
- 按开关懒安装：关闭的功能不 loadClass、不 hook；全关时零额外钩子。
- 反射对象安装期一次性解析成 Field/Method，运行时只做 get/set；高频钩子（`onTextChanged`）把最廉价的长度比较放最前。

### 4.2 按钮几何（真机多轮反馈迭代出的结论）

- 按钮落**键盘抬高区域**（系统 NavigationBarFrame）右侧，与左侧系统「快捷切换输入法」同行同风格（44dp 槽）。
- 尺寸按系统 drawable **墨迹包围盒**（`drawableInkAndColor`：不透明像素 bbox），不按固有尺寸（系统 chevron 固有 92px 但墨迹仅 ≈54px，按固有画必然偏大）。
- 图标色 = 渲染后 alpha 最高像素，必须过 `saneIconColor` 校验（alpha≥0x40 + 明暗方向一致），否则亮键盘上图标消失；渲染色不可信时试 `imageTintList`。
- 面板卡片必须**定高**（容器高比例）+ ScrollView weight=1；WRAP_CONTENT 会在矮键盘上被裁且不滚。

### 4.3 已撤销、勿回填（用户明确决定）

- **模糊模式剪贴板条目变厚**：v1.0.54（负 margin）被日志证伪、v1.0.55（后置 hook `px.u#onBindViewHolder` 压回 48dp/16sp/8dp/24dp）真机仍未修好，**v1.0.56 已整体撤销，用户明言"算了不修这个剪切板面板布局问题了"**。
  根因链（勿重复踩）：`px/u.java#onBindViewHolder` 按 `f4 = he0.p.f39756o/f39757p`（selfScale/appScale）算条目几何；模糊（液态玻璃全高窗口）下 `k71/a.java#C()` 使 selfScale≠appScale（f4≈1.55）⇒ 单行卡 160→255px、列表溢出视口末卡被裁。
  若重新立项：怀疑在**列表级裁切**（URL 卡 <48dp 下限）而非条目级 minHeight，或从 `k71/a#C()`/boardPer 源头入手。
- slotMetrics 取色告警降噪（imageTintList 兜底 + D 级限流）属日志问题，保留。

### 4.4 混淆名稳定性

宿主版本锁定 8.5.303.494（8912）。混淆名在小版本间通常稳定，按名定位相邻版本大概率仍有效；**真正改名时功能静默失效、不崩溃**。宿主升级后需重新用 jadx + apktool 锚定 `E:/WorkBuddy_All/APP/oneplus/decompiled/baiduime`。
