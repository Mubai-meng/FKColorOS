| 角色 | 类 / 方法 | 说明 |

**`b()` 的四个条件**（`AbstractC0818h.java:40`）：

```java

    && (LiveData f14330a == TRUE)      // 系统「质感模糊」开关（ImeApp#onCreate 灌入 e#i() 的值）
    && f14332c                          // 输入应用白名单
    && c();                             // 主题 + 跟随系统深浅
```

⚠️ **`c()` 必须单独 hook，不能只改 `b()`**：`input.manager.k#a()` 里有两处**直接调用 `c()`**（:74 / :94）计算
`themeUtil.f.f14134b`（「夜间也开模糊」），该标志驱动 ImeService 的窗口 blur 标记推送。
只改 `b()` 会让「宿主自己算的 blur 标志」仍为 false，窗口标记不推给框架 ⇒ 模糊出不来。

## 二、模糊增强：改哪几处

| # | 目标 | 手法 | 理由 |
|---|---|---|---|
| 1 | `base.util.h` 全部「无参 + boolean + static」方法（即 `b()`/`c()`） | 恒 true | 按**形状**挂而非按名字（两者都是混淆单字母）；该类里只有这两个符合形状（`a()` 返 int、`d()` void、`e(int)` 返 int） |
| 2 | `base.data.e#i()` | 恒 true | 驱动 LiveData `f14330a` |
| 3 | `Settings.System#getInt` / `getIntForUser` 全部重载 | `system_material_blur_enable` → 1 | `C1089u` 直接读原值并注册监听，改方法返回值才盖得住 |
| 4 | `Settings.Global#getInt` / `getIntForUser` 全部重载 | `disable_window_blurs` → 0 | 框架在宿主进程内自己再读一遍 |
| 5 | `ViewRootManager#setBlurRadius(int)` | 正数替换为配置值，0 保留 | 强度唯一入口；保留 0 的关闭语义 |

### 定位策略：直接类名优先 + DexKit 兜底

上游全用 DexKit（YukiHookAPI 下类名引用不便）。本模块可 `Class.forName`，故：

1. **直接类名** `com.oplus.keyboard.base.util.h` + 形状校验（有无参 boolean 方法）；
2. 失败则 **DexKit 特征**：
   - 旧特征：`paramCount(0) + returnType(boolean) + usingStrings("key_day_night_mode")`；
   - 新特征（1.8.35.17 起字符串挪进 `base.theme.util.f$a#a()`）：找「调用了 `a()` 的无参 boolean 方法」；
3. `e#i()` 的 DexKit 特征：`paramCount(0) + returnType(boolean) + usingStrings("system_material_blur_enable", "SettingsPrefs")`。

### 刻意不碰（与上游一致）

- `utils.h#j()` 折叠判断 —— 被分屏键盘、悬浮工具栏复用，`b()` 拦截后已无需；
- `reflect.a#v()` 版本号 —— 还喂给 appcompat、应用更新，改它风险大于收益。

## 三、下滑快捷键：架构

### 3.1 文件划分

| 文件 | 职责 |
|---|---|
| `SwipeConst.kt` | 动作 id / 名称 / 短标签、键位表、偏好键、阈值上下限 |
| `SwipeConfig.kt` | 从 remote prefs 读一份配置快照；文本非空 ⇒ 归一化为 `A_INSERT_TEXT` |
| `ImeRuntime.kt` | IME 实例、密码框标志、选区、深浅色 |
| `KeyGeometry.kt` | 按键几何（命中测试 / 收集）、KeyCode 换算、T9/手写判定 |
| `EditorActions.kt` | 动作执行（三级降级：`performContextMenuAction` → 反射 → 兜底手写） |
| `ImeClipboard.kt` | 只读宿主剪贴板库取最新条目 |
| `NativePanel.kt` | 打开宿主原生剪贴板 / 快捷短语面板 |
| `SwipeGesture.kt` | 手势识别、按键标签绘制、提示气泡 |
| `hookers/OplusKeyboardHook.kt` | 安装器：7 个钩子 |

### 3.2 七个钩子

| # | 目标 | 时机 | 作用 |
|---|---|---|---|
| 1 | `View#dispatchTouchEvent(MotionEvent)` | 拦截 | 手势入口，按「是不是键盘视图」过滤 |
| 2 | 键盘视图类 `onDraw(Canvas)`（兜底 `dispatchDraw`） | 后置 | 画按键标签；**首次 DOWN 时才挂**（此时才知具体类） |
| 3 | `InputMethodService#onCreate` | 后置 | 捕获 IME 实例 |
| 4 | `InputMethodService#onStartInput(EditorInfo,boolean)` | 前置 | 记录密码框标志 |
| 5 | `InputMethodService#onConfigurationChanged(Configuration)` | 后置 | 刷新深浅色 |
| 6 | `InputMethodService#onUpdateSelection(6×int)` | 后置 | 跟踪选区 |
| 7 | **具体 IME 类**的 `onUpdateSelection` | 后置 | 见 §1.5 |

钩 1 用 `ExceptionMode.PROTECTIVE`（对齐参考模块），异常只记日志原样下放。

**为什么钩 `View#dispatchTouchEvent`**：键盘视图类名是混淆名且随版本变化；`dispatchTouchEvent` 是 `View` 公开方法，
挂一次覆盖所有 View，用「`getSoftKeyboard()` 是否存在」判定键盘视图。非键盘类**负缓存**（仅限
`com.oplus.keyboard` 包内，避免污染 `FrameLayout` 等公共类）。

### 3.3 手势判定

```
DOWN   → chain.proceed()（宿主画按压态）→ 命中键 + 有绑定 ⇒ 记录起点/阈值；无绑定 ⇒ 清状态
MOVE   → |dx| ≤ 容差 且 dy ≥ 阈值 ⇒ 触发
          dy ∈ [阈值×0.8, 阈值) ⇒ 显示预览气泡「X 下滑：动作」
UP     → 未触发则照常下发并清状态
```

**横向容差**：26 键 `max(阈值×2.5, dy×1.2)`；九宫格 `max(阈值×0.9, dy×0.75)`（键更窄更高，手势更"竖"）。

**触发时的关键动作 —— 补发 `ACTION_CANCEL`**：
不能直接 `proceed()`（会把滑动当点击上屏字符），也不能只 `return true`（宿主按压态残留高亮）。
唯一干净做法：用 `MotionEvent.obtain` 复制事件、改 action 为 CANCEL、走一次原方法再 `recycle`。
触发后 `triggered=true`，期间所有 MOVE/UP **吞掉**（否则宿主状态机会重新走「按下→抬起」上屏字符）。

### 3.4 与参考模块的三处设计差异

| 项 | 参考模块 | 本模块 | 原因 |
|---|---|---|---|
| 配置通道 | `BroadcastReceiver` + 目标进程 prefs 缓存 + revision 比对 | libxposed remote prefs 直接读 | App 与 hook 读同一份内存镜像，无 IO、无同步延迟 |
| 动作编码 | `FLAG_*` 位标志与动作 id 混编（反编译后糊成一片） | 独立编号 + 显式分类 | 可读性；行为等价 |
| 手势接管 | 参考模块风格 | 二态返回值约定（`null`=未 proceed / 非 null=最终值） | 避免同一 Chain 重复 proceed（行为未定义） |
| 绑定映射 | **反向**（动作 → 键），一个动作只能绑一个键 | **正向**（键 → 动作），同一动作可绑多键 | 反向下绑第二个键会静默清掉第一个，用户看不出原因；正向更符合直觉 |
| 恢复默认/清空 | 不动 `qwertyLabels` | 一并清标签 | 「清空全部映射」后网格应该真的空掉，留半屏旧标签会让人以为没清干净 |

### 3.5 键面标签三态（v1.1.53 补）

标签是**纯显示层**，与动作完全解耦 —— 隐藏标签不影响下滑触发，禁用下滑也不影响自定义标签显示。

| 状态 | 存储值 | 键面显示 |
|---|---|---|
| 自动 | prefs 无该键 / 空串 | 动作短名（`复制`/`选后`…）；无动作则不画 |
| 隐藏 | `__HIDDEN__`（哨兵） | 不画 |
| 自定义 | 归一化后 1..4 码点 | 原样 |

- 归一化规则与参考模块 `Config.normalizeLabelValue` 一致：`\n`/`\r` 换空格 → `trim` → **按码点**截断到 4；
  **哨兵必须原样透传**，否则「隐藏」会被当成普通 4 字符文字。
- 绘制侧解析顺序（`SwipeConfig.resolveLabel`）：哨兵 ⇒ 空串；非空 ⇒ 自定义；否则动作短名；
  只有 `A_NONE` 才返回空串 —— **禁用键要画「禁用」**（参考模块同行为，这反而是有用信息）。
- ⚠️ **解析必须在「跳过」之前**：早期写法是「无动作就 `continue`」，会把「未绑定但设了自定义标签」的键
  一并跳掉，与参考模块行为不符。

## 四、踩坑记录（改这块前必读）

1. **`InputMethodService` 的包名是 `android.inputmethodservice`，不是 `android.view.inputmethod`**。
   写错会报一堆 `Unresolved reference 'currentInputConnection'` / `'switchToNextInputMethod'`，
   看着像 API 不见了，实际是 import 错包。

2. **Kotlin 块注释支持嵌套**。KDoc 里写路径 `hook/xiaobuswipe/*` 会引入 `/*` 把外层注释**提前截断**，
   编译器报 `Syntax error: Unclosed comment`。路径里不要出现 `/*`（本模块已改成「各文件」）。

3. **`InputConnection#getSelectedText()` 编译期解析到桩类**：`hidden-api-stub` 模块提供了
   `android.view.inputmethod.InputConnection` 的同名桩，编译时报 `Unresolved reference 'selectedText'`。
   改用 `Reflect.callByName(ic, "getSelectedText")` 绕开。

4. **`View.MeasureSpec` 是内部类**，Kotlin 里 `View.MeasureSpec.xxx` 解析不到，必须写全
   `android.view.View.MeasureSpec`。

5. **`Dialog` 没有 `decorView`**：IME 窗口链是 `InputMethodService#getWindow() → Dialog` →
   `Dialog#getWindow() → Window` → `Window#getDecorView()`。

6. **`dp()` 返 Int、`thresholdPx` 是 Float**：`minOf(Int, Float)` 无法推断类型，必须显式 `.toFloat()`。

7. **自定义文本必须同时写进 actions map**：只写 texts map 会让 `actionForQwerty` 返回 `A_NONE`，
   手势侧直接判「未绑定」，整条链路静默不触发。归一化语义 = 文本非空 ⇒ 动作归 `A_INSERT_TEXT`。

8. **标签字号用 `density` 而非 `scaledDensity`**：键面上的图形文字不该跟随系统字体缩放；
   且 `scaledDensity` 已废弃。

10. **「点击设动作」与「长按设标签」是两件事，不能合并**：把长按做成「编辑自定义文本」等于
    把动作和标签混成一体，结果丢掉「已绑定但不显示标签」的表达能力，也让用户看到的长按菜单
    与原模块完全不同（原模块是 `自动 / 自定义文字 / 隐藏此按键标签` 三选一）。

11. **标签要画在「跳过」之前**：`drawLabels` 里若先按「无动作/禁用 ⇒ continue」过滤，再取标签文字，
    「未绑定但设了自定义标签」的键就永远不会画 —— 参考模块是反过来的顺序。

12. **`⊘`（U+2298）这类符号不要直接写进界面**：部分系统字体缺字形会渲染成豆腐块。
    隐藏标签的角标改用普通文案（`隐藏`/`Hidden`）。

9. **`IOException` 类的空缓存文件不是损坏**：`kotlin/compileDebugKotlin/.../*.tab_i.len`、
   `*.keystream` 天然是 0 字节 / 全零，`_scan_zero.py` 会报出来，属正常。

10. **⭐ v1.1.43 真机失效的根因：默认绑定从未落盘 ⇒ `hasAnyBinding=false` ⇒ 整链静默直通**
    （真机症状：模糊正常、下滑完全无反应、日志里既无报错也无 gesture 记录）

    链路逐层拆开：
    - 设置页 `list(default = "1")` 的 `default` **只是 UI 展示值**，不带写入动作。
      用户没手动改过 `z`，prefs 里 `xiaobu_swipe_action_q_z` 就**不存在**；
    - hook 侧老代码 `readAction()` 把「prefs 空串」当作 `A_NONE`，于是 26 键一个都没绑定；
    - `SwipeConfig.hasAnyBinding=false` ⇒ `onTouch()` 第 125 行第一分支 `return null` 直通，
      **不打任何日志**（当时该分支无日志），从日志完全看不出是「没装钩子」还是「没绑定」。

    修复三处，缺一不可：
    ① `readAction(key, fallback)` 增加 fallback 参数，空串回落 `DEFAULT_QWERTY`（九宫格传 `A_NONE`）；
       注意区分「空串=没存过」与 `"0"`=用户显式选了未绑定 —— 后者必须尊重用户选择；
    ② `SwipeGesture.onTouch` 的直通分支补一次性诊断日志（key 带 `enabled`/`hasAnyBinding` 两个状态位，
       状态变了才重打，不刷屏）；
    ③ 绑定页 `currentAction()` 用**同一套回落规则**，否则界面显示 `z=全选`、hook 却认为未绑定。

    **通用教训**：凡是「UI 有默认值、hook 侧也要用同一默认值」的配置，默认值必须在**读取侧**兜底，
    不能只写在 UI 的 `default` 参数里。UI default 与读取 default 是两套独立逻辑，天然会漂移。

11. **`ScopeContentScope` 槽位页的行声明必须留空但构造器不能省**：`contentMiuix`/`contentMaterial`
    非空时整页由页面自有布局渲染，共享层不再绘制任何行；此时 `content` 尾随 lambda 仍必须提供
    （它是构造器最后一个必填参数），但里面不要写任何 `switch`/`list`。同时必须声明
    `selfRendered = true`，否则空索引会让 `hasVisibleContent()` 判假、子页入口直接从父页消失。

12. **自带整页布局的底部固定栏要留 `LocalShellBottomInset`**：Miuix 骨架里
    `LocalBottomBarPresent provides true`，`materialBottomInset` 的 navInset 因此归零，
    只剩 `LocalShellBottomInset`（悬浮胶囊相对 innerPadding 的溢出量）。底栏不加这份 bottom padding
    会被胶囊压住一半，「保存并应用」按钮首尾被遮。

13. **`import androidx.compose.foundation.layout.weight` 会编译失败**：`weight` 是
    `RowScope`/`ColumnScope` 的成员扩展，不是顶层函数。误 import 报
    `Cannot access 'val RowColumnParentData?.weight: Float': it is internal in file`。
    直接在 `Row`/`Column` 作用域里用即可，不要 import。

14. **⭐ 「下滑打开剪贴板」炸出一层工具箱图标压在键位上**（v1.1.54 真机）

    现象：日志只有 `panel -> n() 调用内部抛出：ClassCastException` +
    `所有 n() 重载都不接受参数`，界面上「工具箱」标题与一批工具图标（键盘选择/表情/语音输入/
    剪贴板/全选/剪切/复制/粘贴/翻译/AI 写作…）正好落在各键位上，键面文字还在它们下面。

    根因链（`e#c` 与 `t` 的 case 16 对照即可看出）：
    - 老实现把 headType 猜成 `b$d`，而 `e#c` 里 `b$d ⇒ new input.toolbox.b(context)` = **工具箱**；
      剪贴板/短语面板是 `b$f ⇒ new body.H(context)`；
    - `t(16)` 的 case 16 第一行是 `H h = (H) view` ⇒ 收到工具箱视图必然 **ClassCastException**；
    - 关键：`base#n` 的顺序是 **`linkedHashMap.put` → `addView` → `lVar.invoke(view)`**，
      异常抛在最后一步，**视图已经进容器了** ⇒ 屏幕上留下那层错位图标。
    - 老实现还「两种参数顺序都试一遍」：`base#n(Function1, Object)` 会命中 `(handler, headType)`，
      于是**每个错顺序都是一次「先 addView 再抛异常」**，双份污染。

    修复（`NativePanel.kt` 重写）：
    ① headType 固定取 `b$f`（取不到才退化为扫描，且必须 `isInstance(b)`）；
    ② 参数顺序按 `parameterTypes` 判定：`p[0]` 能收 headType ⇒ `(headType, handler)`，
       否则 `p[1]` 能收 ⇒ `(handler, headType)`。**只发一次调用**；
    ③ 调用后用 `a#d(headType)` 取回真视图校验类名必须是 `body.H`，不符或抛异常则
       `a.h(manager)`（静态）回滚隐藏，绝不留脏面板；
    ④ 短语页由 `t(19)` 承担（`H#t(false)` 内部会 `selectSegmentAt(1)`），不再需要
       「80ms 后去视图树里找 H 再 t(true)」的 hack；`t` 类若被改名，则退化为自建
       `Function1` 动态代理，直接调 `H#q()` / `H#t(false)`。

| 参考模块 | 为何不移植 |
