# Debug 包体积分析与优化（2026-11-24）

## 一、结论速览

| 阶段 | debug APK | 说明 |
|---|---|---|
| 优化前 | **68.33 MB** | 5 个 dex 全 STORED 原样占位 |
| + dex 改 DEFLATE | **22.49 MB** | 最大单项收益，省 45.8 MB |
| + 清理死依赖 | **22.12 MB** | 再省 0.37 MB |
| + 图标库迁移（core + 手写 43 个）+ 删 4 个 Lottie | **17.37 MB** | 再省 4.75 MB，见 4.4 / 4.5 |
| **合计** | **17.37 MB** | **-74.6%，省 50.96 MB** |
| （实验）再开 debug R8 | 4.05 MB | 需评估，见第五节 |

> 表内为十进制 MB（1 MB = 10⁶ B），与系统文件管理器口径一致。
> 当前产物：`FKColorOS_v1.5.17_debug.apk` = **17,369,470 B**。

release 包一直只有 8.5 MB（R8 + lsparanoid + shrinkResources 三重压缩），
所以「debug 大」不是代码写得多，而是**debug 完全没做任何压缩**。

## 二、68 MB 花在哪：dex 占 94%

优化前 APK 内部构成（按未压缩大小）：

| 条目 | raw | 占比 |
|---|---|---|
| classes.dex | 28.93 MB | |
| classes3.dex | 12.62 MB | |

| lib/ | 0.39 MB | 0.6% |
| 其余（META-INF/kotlin/assets…） | ~0.15 MB | 0.2% |

**关键事实**：567 个条目里 279 个是 STORED（不压缩），合计 64.3 MB —— 也就是
dex 和 arsc 全部原样塞进 zip。这是 AGP 在 `minSdk >= 28` 时的默认行为：
不压缩 dex，安装时可直接 mmap，省一次解压、启动更快。

但代价在 debug 上被放大了：release 有 R8 把 61.6 MB 压到 6.5 MB，
debug 没有 R8，于是 61.6 MB 原样落到用户手机上。

## 四、已实施的优化（本轮已落地并构建验证）

### 4.1 移除构建期版本自增

`app/build.gradle.kts` 原 `readAndBumpVersion()` 在 **Gradle 配置阶段**就
`properties.store()` 写文件，三个副作用：

1. 配置阶段写文件 ⇒ 配置缓存永远不可复用；
2. `versionCode` / 产物名每次都变 ⇒ UP-TO-DATE 判定永远失效，等于每次强迫全量重打包；
3. 同一 commit 重编译产物不一致，无法做体积/行为对比。

已改为 `readVersion()` 纯只读。需要抬版本时手工改 `app/version.properties`。

**验证**：连续构建两次，`versionCode` 稳定在 183 / `versionName` 1.5.12 不再自增。

### 4.2 dex 改 DEFLATE 压缩（最大收益，省 45.8 MB）

```kotlin
packaging {
    dex {
        // AGP 在 minSdk>=28 时默认 STORED（mmap 直读）；改 DEFLATE 换取体积
        useLegacyPackaging = true
    }
}
```

实测压缩率：61.60 MB → 17.80 MB（**28.9%**），各 dex 单独测得
22.7% / 35.3% / 35.6% / 31.3%。

代价：安装时多一次解压、首次启动略慢。对 Xposed 模块（常驻进程、装机即用）
几乎无感，且 release 包也顺带受益（6.5 MB → 约 2.4 MB）。

### 4.3 清理零引用依赖（省 0.37 MB）

逐个用 `grep` 全源码 + `method_field_accesses` 字段访问表双重确认，以下依赖
**源码零引用**，已移除：

| 依赖 | 原体积 | 确认方式 |
|---|---|---|
| `coil-compose` + `coil-network-okhttp` | 0.12 MB / 2553 类 | 全工程无 `AsyncImage` / `ImageRequest` / `coil` 调用 |
| `spiderman`（崩溃捕获） | 0.009 MB | 无 `SimpleCrash` / `CrashHandler` 调用；proguard keep 规则保留 |
| `markwon-html` | — | 无 `HtmlPlugin` |
| `markwon-image` | — | 无 `ImagePlugin` / `CoilImagePlugin` |
| `kotlinx-serialization-protobuf` | — | 仅注释里提到 protobuf，无 `ProtoBuf` 用法 |
| `deviceCompat`（显式声明） | 保留传递引入 | 由 XXPermissions 传递带入，删显式声明不省体积 |

同步清理了 `gradle/libs.versions.toml` 里对应的 8 条 catalog 条目。

**保留不动的**：`libsu`（5 个文件用 `Shell`）、`XXPermissions`（权限工具）、
`betterandroid-ui-component-adapter`（虽未直接调用，但属同族发布单元，拆开风险大于收益）。

### 4.4 删除零引用的 4 个 Lottie 动画（省 0.64 MB）

`app/src/main/res/raw/` 下 4 个 Lottie 动画 JSON 共 **966,429 B（0.92 MB 未压缩）**，
deflate 后 638,299 B（0.61 MB），**已全部删除**：

```
multi_app_volume_dark.json        242,620 B
multi_app_volume_dark_rtl.json    243,953 B
multi_app_volume_light.json       239,420 B
multi_app_volume_light_rtl.json   240,436 B
```

确认零引用的证据：
- 全源码无 `R.raw.multi_app_volume` 引用；
- `getIdentifier` 动态查找仅用于 `com.oplus.metis` 宿主字符串，与本资源无关；
- dexsql `method_field_accesses` 查 `field_name LIKE '%multi_app_volume%'` ⇒ **0 条**；
- 工程里根本没有 lottie 依赖。

推测是从上游 LuckyTool 移植时带进来的残留。删除后 `res/raw/` 只剩
`multimedia_pixelworks_apps_x7.xml`（8,937 B，仍在用）。

### 4.5 图标库迁移：extended → core + 手写 43 个（省 4.11 MB）

**做法**：不手抄 SVG。用 asm 解析 `material-icons-extended:1.7.8` 的 `classes.jar`，
从 `ImageVector.Builder.<init>` 与 `PathBuilder` 的调用序列里机械还原每个图标的
维度、autoMirror、分段结构与逐条路径命令，再生成等价的 Kotlin `ImageVector` 扩展属性。

**落位**：`app/src/main/java/com/fr/colorostools/ui/icons/`（4 个文件 / 43 个图标）

| 文件 | 包 | 图标数 | 图标 |
|---|---|---|---|
| `FilledIcons.kt` | `...icons.filled` | 11 | Android, Apps, Brightness1/3/4/7, BrightnessMedium, Check, Close, MoreHoriz, PictureInPictureAlt, PowerSettingsNew, SignalCellularAlt |
| `RoundedIcons.kt` | `...icons.rounded` | 29 | Adb, AspectRatio, BlurOn, CallToAction, CheckCircleOutline, Colorize, Description, DesignServices, DisplaySettings, ExpandLess/More, Fingerprint, GridView, Memory, Palette, PhoneAndroid, Restore, SaveAlt, Style, Swipe, SystemUpdate(Alt), TouchApp, Update, ViewCarousel, VisibilityOff, Wallpaper, WarningAmber, Widgets |
| `OutlinedIcons.kt` | `...icons.outlined` | 1 | Tune |
| `AutoMirroredRoundedIcons.kt` | `...icons.automirrored.rounded` | 2 | MenuOpen, OpenInNew（`autoMirror = true`） |

**依赖改动**

```kotlin
// gradle/libs.versions.toml
androidx-compose-material-icons-core = { group = "androidx.compose.material",
                                         name = "material-icons-core", version = "1.7.8" }

// app/build.gradle.kts
implementation(libs.androidx.compose.material.icons.core)
```

**验证**

- 生成代码 vs 提取数据**双向比对 43 个图标，0 mismatch**（分段结构、每条命令、每个坐标值）；
- 路径命令 0 个未知操作码，参数个数与 `PathBuilder` 签名全部一致；
- dexsql 复核：`Landroidx/compose/material/icons/%` **11400 类 → 294 类**、**23529 方法 → 641 方法**；
- 手写图标在 dex 内为 4 个 `*Kt` 类 / 47 方法 / 7902 条指令 ≈ **15 KB**，对比原来 ≈19.1 MB；
- `./gradlew :app:assembleDebug` BUILD SUCCESSFUL，dex raw 60.70 → 41.63 MB、dex 压缩后 17.80 → 14.29 MB。

**注意**

- `material-icons-core` 自带 14 个（Home / Lock / Check / Info / Search / PlayArrow /
  MoreVert / Close / Settings / Delete / ArrowBack / KeyboardArrowRight …），
  `gen2.py` 的 `CORE` 集合已排除，不会重复定义；
- 新增图标不要直接加回 extended 依赖，走 `tools/icon-extract/`（含 README 与完整复现步骤）；
- `proguard-rules.pro` 无需为这些图标加 keep 规则——它们是源码且被直接引用，R8 不会裁掉。

**踩坑**

- `ImageVector` 在 `androidx.compose.ui:ui` 的 `ui.aar` 里，不在 `ui-graphics.aar`（后者只有 `PathBuilder`）；
- 多段 path 必须靠 `getNodes()` 返回值切分，不能按命令类型猜；
- `arcTo` / `arcToRelative` 的布尔位参在字节码里是 `1.0f / 0.0f`，生成时要转成 `true / false`；
- 尺寸在字节码里是 `Dp."constructor-impl"(F)F`，直接取那个 float。

**release 侧影响（已验证）**

| 指标 | 优化前 | 优化后 |
|---|---|---|
| release APK | 4,717,483 B | **4,782,803 B（+65 KB）** |
| dex raw | 6.05 MB | 6.59 MB |
| dex 数 | 1 | 1 |
| `Landroidx/compose/material/icons/%` 类 | 0（R8 本已剥光） | 0 |
| `MainHook` 入口 | 保留 | 保留 |
| 签名 | V2+V3 | V2+V3（`apksigner verify` 双通过） |

**release 反而大了 65 KB，属预期**：R8 早就把 extended 库整个裁掉，
所以这笔优化在 release 上**收益为 0**；而 43 个手写图标是**真实的、被引用的新增代码**，
R8 不能裁——多出来就是它们的体积。**这笔优化只为 debug 服务**，
别期望 release 跟着瘦。

抽查 12 个图标名字符串（Filled.Android / Rounded.Adb / Outlined.Tune /
Rounded.Widgets / Rounded.Wallpaper / Rounded.CheckCircleOutline / Rounded.SystemUpdateAlt /
Filled.BrightnessMedium / Filled.PictureInPictureAlt / AutoMirrored.Rounded.MenuOpen /
AutoMirrored.Rounded.OpenInNew …）在 release dex 中**全部存在**，确认未被误裁。

## 五、实验：debug 也开 R8 会怎样

临时把 debug 的 `isMinifyEnabled` / `isShrinkResources` 打开做了一次实验：

| 指标 | 不开 R8 | 开 R8 |
|---|---|---|
| APK | 22.12 MB | **4.05 MB** |
| dex 数量 | 5 | 1 |
| dex raw | 60.70 MB | 5.12 MB |
| res 条目 | 446 | 306 |
| `MainHook` 入口类 | 保留 | **保留**（proguard 规则生效） |

体积还能再降 **18 MB（-82%）**。

> 该实验是在 22.12 MB 那一版上做的。本轮图标迁移 + 删 Lottie 之后不开 R8 已降到
> **17.37 MB**，按同一比例估算开 R8 约 **3.2 MB**（**未重跑验证**，仅供估量级）。

**收益**：debug 包也变成 4 MB，装机/传输/分享都轻松。

**风险与代价**（这就是当前 debug 不开 R8 的原因）：

1. **堆栈不可读**：R8 后类名方法名全变 `a.b.c`，线上问题只能靠
   `mapping.txt` 反解。debug 包的价值本来就是「出问题能看堆栈」。
2. **hook 目标反射风险**：模块大量用 `callByName` / `findMethodByShape` 反射宿主方法。
   R8 只混淆模块自己的代码、不动宿主，理论上安全；但模块内若有「靠自身类名字符串
   做反射」的写法（如 lsparanoid 的 `@Obfuscate` 区域），叠加 R8 会双重改名。
3. **构建变慢**：实测 1m10s → 2m35s（+2.2 倍）。
4. **产物不再与源码一一对应**：调试期改一行要等 R8 全量重跑。

**建议**：保持 debug 不开 R8（体积已从 68 MB 降到 **17.37 MB**，足够用）。
如果确实需要小包分发，另加一个 `benchmark`/`slim` buildType，而不是污染 debug。
