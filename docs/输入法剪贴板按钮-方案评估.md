# 输入法剪贴板按钮（键盘抬高区域右侧）— 方案评估

> 宿主：`com.baidu.input_oppo`（百度输入法定制版 8.5.303.494，逆向素材 `E:/WorkBuddy_All/APP/oneplus/decompiled/baiduime`，jadx + apktool 双份齐全）
> 目标：复刻 HyperOS 小米输入法的**键盘右下角剪贴板按钮**——键盘右下角浮动小按钮，点击弹出剪贴板历史面板，点击条目直接把内容输入到当前输入框。
> 结论先行（**v1.0.38 修订**）：**可行。最终方案 = 单钩子注入自绘按钮（键盘抬高区域右侧）+ 点击直接调起输入法自带剪贴板面板**（工具栏「剪贴板」同一个 `ImeCLipListActivity`），历史由输入法自维护，本模块零面板零监听；自绘面板降级兜底（仅宿主升级致原生组件缺失时启用）。

## 2. 需求拆解（HyperOS 小米输入法剪贴板按钮的形态）

1. **入口**：键盘右下角浮动小按钮（剪贴板图标），半透明圆底，不占键盘按键位、浮在按键上层；
2. **面板**：点击按钮，从键盘底部弹出剪贴板历史面板（覆盖键盘区域），顶部标题「剪贴板」+ 收起按钮；
3. **条目**：每条剪贴内容（文本，2 行截断预览）+ 删除小钮；点击条目 → **直接输入到当前输入框**并收起面板；
4. **自动记录**：复制自动入历史（去重、最近优先、上限约 20 条），**持久化**（重启输入法/重启手机后仍在）；
5. **边界**：密码框等不可见输入场景禁用；空历史有空态文案。

**关键判断**：主键盘场景（含横竖屏、皮肤切换、语言切换）最终都收敛到 `l30.b` 这个 FrameLayout，且 `setInputView` 是 InputMethodService 的标准 API（百度换版本极难改它），钩子稳定性高；`mx.b`（fakeSoftView）是特殊分支，钩子体做 `instanceof ViewGroup` 判断即可安全跳过。

**按钮落位结论（2026-10-16 用户实测纠正）**：用户反馈按钮必须落在**键盘抬高区域**（键盘最底部系统嵌入条）右侧，与左侧系统「快捷切换输入法」按钮同行同风格；插输入法自绘工具栏是错方向。抬高区域由框架绘制、挂在 IME 窗口 DecorView 底部，按钮经 DecorView 反射链插入；框架侧 `clipboard` 按钮类型无布局，系统层面不可用，故自绘插入。

**v1.0.38 面板方案变更（用户指定："点击直接调用输入法自带的剪切贴板面板，性能更好"）**：jadx 全库复勘发现宿主**有**完整原生剪贴板体系（上表后 6 行），且 `ImeCLipListActivity` 就是工具栏「剪贴板」按钮打开的面板。改为：按钮点击 → 显式 Intent 调起该 Activity（参数复刻工具栏路径）；自绘面板整体降级为兜底。收益：历史记录/持久化/条目输入全部由输入法原生完成，本模块常驻物只剩 1 个按钮；用户三条反馈（按钮尺寸、面板滚动、IME 重弹自动开面板）也随之消解——原生面板自己管显隐。

## 4. 钩子设计

### 4.1 安装与分发（对齐工程现有约定）

1. `HookEnv` 新增常量 `PKG_BAIDU_INPUT = "com.baidu.input_oppo"`；
2. `MainHook.installForPackage()` 新增分支：命中该包 → `ImeClipboardButtonHook.install()`（进程级 `AtomicBoolean` 防重复）；
3. `scope.list` 新增单宿主（附验证注释）；
4. 配置键 `ime_clipboard_button_enabled`（remote prefs，App 侧 `SettingsPrefs` 写、hook 侧 `HookEnv.settingBoolean` 读）。

### 4.2 钩子体（单钩子）

```
hook ImeService#setInputView(View)  // after
  ├─ 开关关闭 / 已注销 → 摘按钮+面板 return
  ├─ view !is ViewGroup → 记一行 D 日志 return（fakeSoftView 等特殊容器）
  └─ 注入按钮（每次摘旧重建，不查 tag）：
       ① 首选：DecorView 反射链 → 按类名找 NavigationBarFrame →
          addView(34dp × MATCH_PARENT, Gravity.END|CENTER_VERTICAL)
       ② 未就绪（键盘抬高低关闭 / 装帧竞态）→ 先浮动兜底（键盘容器右下角 8dp 边距），
          同时起 post 重试链（最多 8 次一帧）：Frame 装好后把「仍是当前这枚
          （button === btn）且仍在浮动父容器里」的按钮迁移进抬高区域
```

- **幂等**：按钮挂在系统 NavigationBarFrame（**不在输入法视图树内**），`findViewWithTag` 不可用 → 每次 `setInputView`（onStartInputView 都会重调）先摘旧再按当前键盘明暗重建；
- **迁移链自废**：重复 `setInputView` 换新按钮后，旧按钮的重试链因 `button !== btn` 检查直接作废，不会把过期按钮插进抬高区域；
- **事件优先级**：NavigationBarFrame 是 FrameLayout，addView 的子 View 位于 z-order 最上层，点击先派到按钮；
- **按钮形态**：自绘 `View`（纯代码画剪贴板图标，不依赖宿主资源），**无底色纯图标**（对齐系统 ime_switcher 风格，同条同高）；图标色随键盘明暗（浅键盘→深色 `0xDE000000`，暗键盘→白）；按压 alpha 0.5 反馈；
- **明暗检测**：读键盘根容器（`l30.b`）背景主色算亮度（ColorDrawable/GradientDrawable），取不到回退系统 `UI_MODE_NIGHT`；
- **onDestroy 清理**：hook `ImeService#onDestroy` 后置注销剪贴板监听 + 清全部引用（按钮随 Frame/容器销毁自然释放）。

### 4.2.1 点击分发（v1.0.38 核心变更）

```
按钮 onClick（安全输入场景 → 直接 return）
  ├─ openNativeClipboard()：PackageManager.getActivityInfo(com.baidu.input_oppo/
  │    com.baidu.input.ImeCLipListActivity) 解析成功
  │    → Intent{component, key=48424, entry_play_animation=true, NEW_TASK}
  │    → ctx.startActivity  ⇒ 输入法原生剪贴板面板（工具栏「剪贴板」同一个）
  └─ 解析/启动失败（宿主升级改名）→ 记 W 日志 → togglePanel() 自绘兜底面板
```

- **幂等/竞态**：原生 Activity 是 `singleTask` + 独立 `taskAffinity`，重复拉起不会叠窗；面板显隐由输入法自己管，IME 收起再弹不自动开（自绘兜底面板另有 `onStartInputView`/`onFinishInputView`/`setInputView` 三处 dismiss 保险）；
- **后台启动限制**：点击发生在 IME 窗口可见期，进程状态与工具栏点击完全一致（同在输入法进程），不受 BAL 限制；
- **安全输入**：`getCurrentInputEditorInfo().inputType` 含密码类 variation 时不展示（隐私），与兜底面板策略一致。

### 4.3 自绘兜底面板（懒创建，仅原生组件缺失时启用）

- 默认路径为原生面板（§4.2.1）；本面板仅当 `getActivityInfo` 解析失败（宿主升级改名/组件被裁）时启用；
- 第一次走兜底点击才创建面板 View 并 `addView` 到同一 FrameLayout（`MATCH_PARENT × 键盘高度`，`BOTTOM` 对齐），此后只切显隐；
- 结构：标题栏（「剪贴板」+ 收起按钮）+ 条目列表（`LinearLayout` 手写条目，条目不超 20 个，无需 RecyclerView）+ 空态文案；
- **配色跟随键盘明暗**（`ClipPanelView(isDark)`，十色参数化）：浅色键盘上白卡深字（accent `0xFF1A73E8`），暗键盘上深卡白字（accent `0xFF8AB4F8`）——浅键盘不再出违和黑面板（2026-10-16 用户反馈）；键盘明暗切换时摘旧建新；
- **初始 GONE**：刚 addView 完若为 VISIBLE 会撞上「已 VISIBLE ⇒ dismiss」分支永远打不开；
- 条目 = 内容预览（`TextView`，2 行截断）+ 删除小钮；点击条目区域 → `commitText` 输入并收起；
- 返回键：面板 `setFocusable(true)` + `requestFocus()` + `setOnKeyListener` 吞 `KEYCODE_BACK` 收起面板（兜底：吞不掉时 back 关键盘，体验可接受）；
- 密码/不可见输入场景（`EditorInfo.inputType` 含 `TYPE_TEXT_VARIATION_PASSWORD` 等，或 `getCurrentInputConnection() == null`）：按钮置灰不可点（降透明度 + `isEnabled=false`）。

## 5. 数据层（剪贴板历史）

> **v1.0.38 起默认路径无本模块数据层**——原生面板的历史由输入法自维护（`ly.b` ClipManager 监听复制 → `RecordService` INSERT_RECORD → SQLite `clipboard` 表，自带去重/上限/持久化）。下表仅描述**自绘兜底面板**的数据层，懒加载（首次走兜底才注册监听/建库）。

| 项 | 设计 |
|---|---|
| 监听 | `ClipboardManager.addPrimaryClipChangedListener`（系统级回调，**非轮询**）；安装钩子时注册一次 |
| 读取时机 | ① 监听回调触发时读 `getPrimaryClip()`（IME 前台时能读到，读不到跳过）；② **每次展开面板时补读一次当前剪贴板**——若不在历史中且为纯文本则头插入队（覆盖「在其他 App 复制」的场景，IME 后台读不到内容时的补救） |
| 内容过滤 | 只收 `ClipData` 的第一个 `Item` 的 `text`（coerceToText）；非文本（URI 等）跳过；空文本跳过；上限 **20 条**、去重（相同内容上提去旧） |
| 持久化 | IME 进程 `SharedPreferences`（`clip_history_v1`，JSON 数组）；仅在入队时 `apply()` 异步写盘——写盘频率 = 用户复制频率，天然低频 |
| 输入 | `imeService.getCurrentInputConnection().commitText(text, 1)`（调用点取自钩子上下文的 `ImeService` 实例，主线程执行） |
| 线程 | 全部主线程（listener 回调即主线程；JSON 编解码 20 条以内微秒级，无需子线程） |

**Android 13+ 剪贴板隐私说明**：系统复制 toast 不影响监听；`getPrimaryClip` 的前台限制由「展开面板补读」策略兜底（IME 活跃即有焦点，可读）。

## 6. 性能设计（重点）

| 关注点 | 措施 |
|---|---|
| 作用域面 | 只注入 `com.baidu.input_oppo` 单进程；hook 4 个方法（`setInputView` / `onDestroy` / `onStartInputView` / `onFinishInputView`），均为输入法自身低频路径 |
| 常驻内存（默认路径） | **仅 1 个 44dp 自绘按钮**——原生面板由输入法自管，本模块零面板、零监听、零历史库 |
| 常驻内存（兜底路径） | + 1 个面板 View + 1 个 listener + 1 个 SP 历史库（全部懒创建，仅原生组件缺失时） |
| CPU | 无轮询、无定时器、无后台 Service、无线程池；hook 体热路径 = `instanceof` + tag 检查（不匹配即退） |
| 写盘 | 默认路径零写盘（输入法自己写它的 SQLite）；兜底路径仅入队事件触发，`apply()` 异步 |
| 对宿主的影响 | 不改宿主任何逻辑；按钮只消费自己区域的事件；调起原生面板 = 复刻工具栏一次点击，宿主行为零变更 |
| 开关关闭时 | 钩子体首行早退，等效未注入 |

## 8. 风险与对策

| 风险 | 评估 | 对策 |
|---|---|---|
| `l30.b` 被复用 / 子 View 被清 | `onStartInputView` 每次重新 `setInputView` | 每次摘旧重建；迁移链只认当前按钮（`button !== btn` 自废） |
| **反射链拿 null**（`callByName` 只查精确类 `declaredMethods`） | `getWindow`/`getDecorView` 均声明在父类（InputMethodService/Dialog/Window） | 三跳全部 `callDeep`（v1.0.29 实测修正） |
| `mx.b`（fakeSoftView，纯 View）不能 addView | 特殊分支 | `instanceof ViewGroup` 检查，非容器记 D 日志跳过（不影响主键盘） |
| 输入法大版本升级 | hook 的是 InputMethodService 标准公开 API + FrameLayout 容器 | 类/方法找不到只记 W 日志跳过，宿主行为零影响 |
| 深/浅皮肤图标与面板违和 | 主流皮肤为浅色键盘 | 已做明暗适配：图标色随键盘背景亮度切换，面板十色参数化双主题（兜底路径） |
| **原生组件被宿主升级改名/裁掉**（`ImeCLipListActivity` 或 `key` 约定变更） | 中概率（百度改版频繁） | 启动前 `PackageManager.getActivityInfo` 解析 + `startActivity` 双重兜底，失败即回退自绘面板（W 日志可观测）；`key=48424` 为 App 内部跳转约定，多 Activity 共用，变更面小 |
| **原生面板形态 = 半透明浮层列表**（非 HyperOS 键盘内嵌） | 用户已知情选择（"直接调用输入法自带面板，性能更好"） | 若用户后续要键盘内嵌形态：自绘兜底面板已具备（卡片定高 + weight=1 滚动修复），改配置键即可切换主路径 |
| 原生面板打开时 IME 窗口状态 | Activity 半透明覆盖在 IME 之上，IME 保持连接 | 与工具栏点击路径完全一致（同进程同窗口状态），条目点击走输入法原生 commitText |
| 面板返回键吞不掉 | 输入法窗口焦点行为 | 兜底降级为 back 关键盘，可接受 |
| 剪贴板被系统二次清空 | Android 12+ 剪贴板清理属系统行为 | 面板展开时实时补读当前剪贴板，用户看到的永远含最新一条 |
| 跨进程开关延迟 | remote prefs 缓存 | 与现有功能一致（hook 侧缓存 + 重读策略，工程已有先例） |

## 9. 验证计划（构建后真机）

1. 按钮显隐：任意输入框弹出键盘 → **键盘抬高区域右侧**出现按钮（与左侧系统「快捷切换输入法」按钮同行同风格，槽宽/图标/边距与系统按钮对称）；键盘抬高低关闭 → 浮动兜底，Frame 就绪后自动迁移；切横竖屏/皮肤/语言 → 位置与幂等保持；
2. **原生面板（主路径）**：复制一段文本 → 点按钮 → 输入法自带剪贴板面板弹出（半透明浮层）→ 历史含刚复制内容 → 点条目 → 内容输入到输入框；
3. **IME 重弹不自动开**：打开面板后直接收起键盘（返回键）→ 再次唤出键盘 → 面板不自动出现；
4. 兜底路径：临时改 `CLS_CLIP_LIST` 为不存在的类名（或宿主升级后）→ 点按钮 → W 日志「原生剪贴板面板不可用」→ 自绘面板出现，历史/滚动/删除正常（滚动验证：≥3 条时可滚，卡片不被裁）；
5. 边界：密码框点击无反应（D 日志「安全输入场景」）；空历史原生面板有空态；
6. 回归：流体云 / 长按菜单 / 天气 / 无障碍四功能不受影响。
